# ChoreWheel Empty-State Design Specification

## Executive Summary

This design specification documents the improved empty-state UI for the ChoreWheel mobile and desktop dashboard. The design transforms the empty-state from a passive screen into an active onboarding guide that clearly communicates the "what to do next" messaging. Based on the Stitch SDK design artifacts, this specification provides desktop and mobile mockups with proper spacing, responsive breakpoints, and theme guidance for implementation.

### Component Hierarchy

The empty-state component structure follows a clean, accessible hierarchy:

```
EmptyStateContainer
├── IllustrationContainer
│   └── SVG Illustration (240x240px base)
├── TitleText (H3 typography)
├── DescriptionText (Body2 typography)
└── PrimaryCTAButton
    └── SecondaryCTAButton (if needed)
```

### Typography and Spacing

**Typography Guidelines:**
- Primary message: H3 font size (20px) with 1.2em line height
- Secondary description: Body2 font size (14px) with 1.4em line height
- Font family: Inter (as specified in project requirements)
- Weight: Primary text bold, secondary text regular

**Spacing System:**
- Vertical rhythm: 16px baseline
- Horizontal padding: 8px minimum for mobile, 16px for desktop
- Section spacing: 24px between illustration and text
- Button spacing: 16px between CTAs

### Responsive Behavior

**Breakpoints:**
- Mobile (sm): 640px and below
- Tablet (md): 768px and above
- Desktop (lg): 1024px and above

**Mobile Responsiveness:**
- Full-width layout with 16px horizontal padding
- Illustration scaled to 100% width (max 240px)
- Button stack vertically with 16px spacing
- Touch targets minimum 44x44px

**Desktop Responsiveness:**
- Centered container with max-width 600px
- Two-column layout (illustration left, text right)
- Consistent spacing and typography scaling

### Accessibility Requirements

**WCAG 2.1 AA Compliance:**
- Minimum 4.5:1 color contrast ratio for text
- Semantic HTML structure with proper heading hierarchy
- ARIA labels for interactive elements
- Focus management for keyboard navigation
- Screen reader support for all visual elements

**Touch Target Requirements:**
- All interactive elements: 44x44px minimum
- Sufficient spacing between touch targets (8px minimum)
- Clear visual focus indicators

### Theme and Branding Guidance

**Color Palette:**
- Primary: #6366F1 (indigo) for CTAs and highlights
- Secondary: #E5E7EB (light gray) for background
- Text: #1F2937 (dark gray) for primary text, #6B7280 (medium gray) for secondary
- Accent: #F59E0B (amber) for important notifications

**Brand Voice:**
- Friendly and approachable
- Clear and direct communication
- Encouraging tone to guide users

## Conclusions and Recommendations

The improved empty-state design successfully transforms the passive screen into an active onboarding guide by:

1. **Clear messaging**: The "what to do next" guidance is immediately apparent
2. **Visual hierarchy**: Proper typography and spacing guide the user's eye
3. **Responsive behavior**: Works seamlessly across all device sizes
4. **Accessibility compliance**: Meets WCAG 2.1 AA standards
5. **Brand consistency**: Aligns with existing design system
